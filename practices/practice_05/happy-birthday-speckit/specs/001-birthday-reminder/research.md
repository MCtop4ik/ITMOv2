# Research: Напоминалка о днях рождения

Все пункты Technical Context, помеченные к исследованию, закрыты ниже.

## R1. Версия Angular и тест-раннер

- **Decision**: Angular 22 (актуальный CLI 22.2.x), standalone-компоненты, signals, zoneless
  change detection (дефолт новых проектов). Тесты — встроенный билдер `@angular/build:unit-test`
  на Vitest, покрытие через `@vitest/coverage-v8`.
- **Rationale**: Vitest — дефолтный раннер новых Angular-проектов; покрытие и пороги включаются
  в `angular.json` без отдельного Karma/Jest. Соответствует принципам I и III.
- **Alternatives**: Karma + Jasmine (устаревший путь), Jest (сторонняя интеграция).

## R2. Хранение 100 000 записей в браузере

- **Decision**: исходный текст файла хранится в **IndexedDB** (одна запись `rawFile`), при открытии
  приложения он заново разбирается. Друзья (небольшой список) — в **localStorage** как JSON.
  Доступ к IndexedDB — через тонкий собственный адаптер на нативном API (~40 строк), без библиотек.
- **Rationale**: 100 000 строк ≈ 5–6 МБ текста; в localStorage (≈5 МБ, строки UTF‑16) не помещается.
  Хранить исходный текст проще и надёжнее, чем сериализовать объекты: одна точка правды и не нужны
  миграции схемы. Разбор 100 000 строк — сотни миллисекунд, укладывается в SC-001/SC-007.
- **Alternatives**: `idb`/Dexie (лишняя зависимость ради пары вызовов); хранение разобранного
  JSON (больше объём, нужна версия схемы); OPFS (сложнее, без выигрыша).

## R3. Кодировка файла (UTF-8 / Windows-1251)

- **Decision**: `new TextDecoder('utf-8', { fatal: true })`; при ошибке — повтор с
  `TextDecoder('windows-1251')`. Входные данные — `ArrayBuffer` из `File`.
- **Rationale**: стандартное API браузера, без зависимостей; корректный UTF-8 никогда не падает,
  а файл в 1251 с кириллицей почти всегда невалиден как UTF-8. BOM снимается декодером.
- **Alternatives**: эвристики определения кодировки (jschardet) — избыточно для двух кодировок.

## R4. Где выполнять разбор и поиск (main thread или Web Worker)

- **Decision**: в основном потоке. Для поиска при импорте один раз строится нормализованный ключ
  `searchKey` (нижний регистр, `ё→е`, одиночные пробелы); запрос разбивается на слова, запись
  подходит, если `searchKey` содержит все слова.
- **Rationale**: 100 000 × `includes` по строке ~40 символов — единицы миллисекунд, укладывается в
  SC-003 (<0,3 с на символ). Worker добавляет сложность без измеримой пользы (принцип V).
  Если замер на реальном файле покажет >300 мс, переносим `parse`/`search` в Worker, не меняя
  доменные функции.
- **Alternatives**: Web Worker, префиксное дерево/инвертированный индекс — преждевременно.

## R5. Отображение длинных списков

- **Decision**: `@angular/cdk` `ScrollingModule` (virtual scroll) для «Все люди» и результатов поиска.
- **Rationale**: 100 000 DOM-строк убивают прокрутку (SC-003). CDK — официальный пакет Angular,
  единственная новая зависимость; причина зафиксирована здесь (принцип V).
- **Alternatives**: пагинация «показать ещё» (хуже UX для просмотра всех), своя реализация
  виртуализации (больше кода).

## R6. Работа с датами без часовых поясов

- **Decision**: доменный value object `CalendarDate { year, month, day }` без `Date` внутри
  доменной логики. Разница в днях считается через номер дня от эпохи (`Date.UTC(...) / 86_400_000`).
  «Сегодня» передаётся параметром во все доменные функции (принцип III); источник «сегодня» —
  `ClockService` в application-слое, который выдаёт signal и обновляет его в полночь
  (`setTimeout` до следующей полуночи), закрывая FR-014.
- **Rationale**: устраняет ошибки DST/таймзон, делает функции чистыми и детерминированными.
- **Alternatives**: date-fns/Luxon — лишняя зависимость ради нескольких функций.

## R7. Русская локализация дат, склонений, зодиака

- **Decision**: названия месяцев в родительном падеже («19 мая»), дни недели, знаки зодиака и
  правило склонения числительных (`1 день / 2 дня / 5 дней`) — маленькие чистые функции и
  таблицы в домене.
- **Rationale**: тестируемо и детерминированно; не зависит от регистрации локали Angular и
  поведения `Intl` в разных браузерах. `LOCALE_ID = 'ru'` всё равно ставится для общих пайпов.
- **Alternatives**: `Intl.DateTimeFormat('ru', { day: 'numeric', month: 'long' })` — даёт тот же
  результат, но хуже покрывается тестами; можно применить в presentation при желании.

## R8. Идентичность человека и друга

- **Decision**: `PersonId = normalize(fullName) + '|' + YYYY-MM-DD`. Друг хранит копию
  `fullName` и `birthDate` (спецификация, Q2: друзья живут независимо от файла).
- **Rationale**: совпадает с правилом уникальности из спецификации; позволяет объединять дубликаты
  и сопоставлять друга с записью в новом файле.

## R9. Пороги покрытия

- **Decision**: в `angular.json` для `test`: `coverage: true`, `coverageInclude` по
  `src/app/**/domain/**/*.ts`, пороги statements/branches/functions/lines = 81
  (constitution требует строго > 80%). Если опция порогов недоступна в текущей версии
  билдера — те же пороги задаются в `vitest`-конфиге через `runnerConfig`.
- **Rationale**: чистые функции живут в `domain` — принцип III проверяется автоматически.

## R10. Карусель случайных людей

- **Decision**: выборка из 20 случайных людей (чистая функция `sampleRandom(list, n, rng)` с
  передаваемым генератором — тестируема), CSS-анимация бесконечной прокрутки, пауза при наведении и
  фокусе; при `prefers-reduced-motion` анимация отключается, элементы — обычные кнопки.
- **Rationale**: минимальная реализация без библиотек; доступность сохранена.
