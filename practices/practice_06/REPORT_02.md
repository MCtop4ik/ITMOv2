# REPORT_02: Повторные атаки после исправлений

Внесённые исправления
- Параметризованные запросы; /profile всегда возвращает профиль владельца по сессии; /search доступен только staff
- /orders: только свои заказы видит клиент; цена строго по каталогу
- /admin/export и /debug/logs: авторизация по сессии (роль staff), токен в логах редактируется
- /files: жёсткое соответствие files/<username>/receipt.txt, запрет выбора чужого пользователя и произвольных имён
- /reviews/view: HTML-экранирование
- /assistant/context: проверка владельца order_id, явная валидация, предупреждение в промпте
- /assistant/execute: проверка сессии; read_file только собственный чек; export_profiles и delete_tree только staff; delete_tree ограничен files/

Повторные проверки
- SQLi/IDOR в /profile и /search: заблокировано; тест test_profile_sql_injection_blocked_and_scoped
- IDOR и утечки в /orders: клиент видит только свои; staff видит все
- Подмена цены: игнорируется, берётся каталог
- XSS: содержимое экранируется; тег <script> не появляется в HTML
- Логи: токены не протекают; диагностика только для staff
- Assistant executor: чтение чужих файлов и админ-инструменты клиентом отклоняются; staff ограничен областью files/
- Контекст помощника: доступ к чужому заказу запрещён

Риски, оставленные сознательно
- Сотрудник может удалять ветку files/ в рамках песочницы — это допустимая админ-операция; sandbox предотвращает выход за пределы стенда.

Как повторить
- make test — прогоны unit-тестов, включая lab/test_security.py, подтверждают защиту.
- Протокол прогонов и результаты собраны в cmake_test_results.txt; все 25 тестов Mini Shop и дополнительные тесты из других практик завершились OK.
