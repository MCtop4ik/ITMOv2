# REPORT_01: Атаки на исходный сервис

Стенд: локальный Mini Shop (HTTP на 127.0.0.1, SQLite in-memory, sandbox файлов). Ниже — найденные уязвимости и воспроизведение.

1. SQL Injection и IDOR в /profile и /search
- Проблема: строковая конкатенация SQL, клиент может передать любой id/q. Пример: GET /profile?id=1 OR 1=1, GET /search?q=%' OR '1'='1
- Эффект: выдача всех профилей, утечка PII.

2. IDOR и утечка заказов в /orders
- Проблема: выдавались все заказы всем.
- Эффект: клиент видит чужие заказы.

3. Подмена цены в /orders
- Проблема: клиент мог передать price в теле и купить по произвольной цене.

4. Privilege escalation через X-Role
- Проблема: /admin/export доверял заголовку X-Role, клиент мог сам указать staff.

5. IDOR файлов и Path Confusion в /files
- Проблема: путь собирался из user и path; клиент мог читать files/bob/receipt.txt и пытаться читать служебные файлы.

6. XSS в /reviews/view
- Проблема: отзывы вставлялись как HTML без экранирования. <script> исполняется в браузере.

7. Утечка секретов через /debug/logs
- Проблема: endpoint открыт, логи содержали заголовки с токенами.

8. Небезопасный исполнитель AI (/assistant/execute)
- Проблема: инструменты read_file, export_profiles, delete_tree выполнялись без привилегий. Клиент мог читать чужие файлы, выгружать профили, удалять дерево.

9. Контекст помощника выдавал чужой заказ
- Проблема: /assistant/context принимал order_id без проверки владельца и строил SQL строкой.

Доказательства: см. исходные тесты и добавленные security-тесты (lab/test_security.py), которые на уязвимой версии падают.
