# Research: Анимации интерфейса

Решения приняты по последовательности скилла `animate` (философия Эмиля Ковальски): сначала
«нужна ли анимация вообще» и «какая у неё цель», потом инструмент, свойства, кривая, длительность,
прерывание, reduced motion.

## R1. Инструмент: CSS + встроенные `animate.enter` / `animate.leave` Angular

- **Decision**: CSS-переходы и `@starting-style` для появления; встроенные в Angular 22
  `animate.enter="класс"` / `animate.leave="класс"` для элементов, которые исчезают из `@if`/`@for`.
- **Rationale**: самый дешёвый инструмент, который закрывает задачу, и без новых зависимостей
  (принцип V). `@angular/animations` устарел, Motion-библиотека для фейдов не нужна. Переходы
  (а не keyframes) подхватываются с текущего значения при повторном срабатывании (FR-008).
- **Alternatives considered**: `@angular/animations` (устарел, тяжелее); View Transitions API
  через `withViewTransitions()` (на время перехода перекрывает страницу снимком и блокирует
  клики, что противоречит SC-003); Motion/WAAPI (не нужны: нет жестов и пружин).

## R2. Общие токены

- **Decision**: добавить в `:root` в `src/styles.css`:
  `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`, `--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`.
  Длительности указываются по месту (таблица в `contracts/motion.md`), отдельную шкалу не заводим.
- **Rationale**: своих токенов движения в проекте нет, а встроенный `ease-out` слишком слабый.
  `ease-in` в интерфейсе не используется.

## R3. Гейт по частоте и цель для каждого элемента

| Элемент | Частота | Цель | Решение |
|---------|---------|------|---------|
| Нажатие кнопки / карточки карусели | десятки раз в день | Отклик на действие | `scale(0.97)`, 160 мс |
| Наведение на кнопку | десятки раз в день | — | Оставить мгновенную смену цвета (так задумано в брутальном стиле), без движения |
| Подтверждение «… теперь в друзьях» | изредка | Отклик на действие | Появление и уход через переход + автоскрытие |
| Удаление строки друга | изредка | Пространственная связность | Строка затухает и схлопывается, соседи едут вверх |
| Итог импорта | изредка | Индикация состояния | Появление |
| Смена экрана | десятки раз в день | Сгладить резкую смену | Почти незаметный фейд 150 мс, без сдвига |
| Блоки главной | несколько раз в день | Сгладить резкую смену | Лёгкий каскад, 50 мс между блоками |
| Столбцы статистики | изредка | Индикация состояния | Рост от базовой линии |
| Праздник в день рождения | редко | Радость | Конфетти один раз за сессию |
| Строки списка 100 000 человек, результаты поиска | постоянно | — | **Без анимации** (FR-010) |
| Переключатель «В друзья» в списке людей и карточке | часто | — | Без отдельной анимации: достаточно смены подписи и отклика на нажатие |

## R4. Удаление строки: соседи без FLIP

- **Decision**: класс в `animate.leave` переводит `<li>` к `opacity: 0` и схлопывает его высоту
  через `grid-template-rows: 1fr → 0fr` (внутренняя обёртка с `overflow: hidden`), 200 мс `--ease-out`.
- **Rationale**: соседние строки сдвигаются сами, потому что меняется высота, и не нужен
  JS-замер (FLIP). Анимировать высоту допускается для схлопывания, как в аккордеоне; держим её короткой.
- **Alternatives considered**: FLIP через WAAPI (больше кода), View Transitions (см. R1).

## R5. Подтверждение о добавлении — переход, а не keyframes

- **Decision**: появление `opacity 0→1` + `translateY(-8px→0)` через `@starting-style`; уход через
  `animate.leave` по тому же пути; 250 мс `--ease-out`. Автоскрытие через 4 с, кнопка «Скрыть»
  остаётся, повторное добавление сбрасывает таймер.
- **Rationale**: в рецепте тоста 400 мс `ease`, но спецификация ограничивает отклик 300 мс
  (FR-007), поэтому берём 250 мс `--ease-out`. Уходит тем же путём, каким появилось. Без
  автоскрытия не выполняется сценарий US1-1 («плавно исчезает»).

## R6. Смена экрана без блокировки ввода

- **Decision**: в `src/styles.css` правило `main.page > router-outlet + *` (хост
  маршрутизируемого компонента): `display: block; transition: opacity 150ms var(--ease-out);
  @starting-style { opacity: 0 }`.
- **Rationale**: `<main class="page">` постоянный, а хост страницы монтируется заново на каждый
  маршрут, поэтому `@starting-style` срабатывает. Меняется только прозрачность, элемент сразу
  кликабелен (SC-003). Без сдвига, потому что навигация частая.

## R7. Столбцы статистики: `scaleX` от базовой линии

- **Decision**: `.bar { transform-origin: left; transition: transform 300ms var(--ease-out);
  @starting-style { transform: scaleX(0) } }`, задержка `calc(var(--i) * 15ms)`, где `--i`
  выставляется из `$index` через `[style.--i]`.
- **Rationale**: ширина остаётся данными (`[style.width.%]`), а анимируется только transform.
  `scaleX(0)` здесь не «появление из ничего», а рост значения от нуля, в этом и смысл анимации.
  Для 12 месяцев: 300 + 11 × 15 = 465 мс ≤ 500 мс (FR-007).

## R8. Праздник: конфетти на CSS один раз за сессию

- **Decision**: в `HomePage` 16 элементов `<span>` с `aria-hidden="true"` и `pointer-events: none`,
  одна общая keyframe-анимация падения/вращения на 1600 мс `--ease-out`, разброс по позиции,
  задержке и цвету через `--i` из `$index` (детерминированно, без случайности). Признак «уже
  показали» хранится в переменной модуля `home.page.ts`, поэтому сбрасывается при перезагрузке
  вкладки (как сказано в Assumptions).
- **Rationale**: редкий момент, на него и тратится «бюджет радости». Keyframes здесь уместны:
  анимация заранее задана, не прерывается и идёт вне главного потока. Библиотека конфетти не
  нужна. Чистых функций не появляется.

## R9. Reduced motion

- **Decision**: оставить глобальное правило `animation: none !important; transition: none !important`.
  Под ним появления становятся мгновенными, конфетти и карусель не двигаются, вся информация видна.
- **Risk to verify**: `animate.leave` должен удалять элемент сразу, если у класса нулевая
  длительность. Проверить вручную в quickstart (шаг 6); если элемент «зависает», классы leave
  внутри `prefers-reduced-motion` задаются без анимации.
